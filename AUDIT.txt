================================================================================

Name:           Fixin Auto
Type:           Demo / portfolio showcase (NOT a real business)
Language:       English (all user-facing content)
Purpose:        A freelance portfolio piece demonstrating two competencies:
                1) Visual interactivity and UX (scroll-driven animations,
                   parallax, responsive design)
                2) Cloud data automation (Google Sheets integration via
                   Apps Script for a live "Guest Wall" feature)

Tech Stack:     Pure HTML5, CSS3, vanilla JavaScript
                No frameworks, no npm, no build tools, no dependencies
                Google Apps Script as serverless backend
                Google Sheets as cloud database

Local Dev:      python3 -m http.server 8000  (from project root)

 7. SCROLL-DRIVEN WHEEL ANIMATION
================================================================================

File:           js/scroll-animation.js (102 lines)
                Wrapped in an IIFE — no global pollution.

7.1  Wheel Rotation + Parallax

     Listener:   window.addEventListener('scroll', onScroll, { passive: true })
                 passive: true prevents scroll jank (browser doesn't wait
                 for preventDefault check).

     Throttling:  requestAnimationFrame with a `ticking` flag.
                  onScroll() sets ticking=true, schedules updateAnimations().
                  updateAnimations() runs once per frame, resets ticking=false.

     Calculations (only run when scrollY < heroH * 1.2):
       rotation  = scrollY * 0.35         degrees clockwise
       parallaxY = scrollY * 0.15         pixels downward
       opacity   = max(0, 1 - scrollY/(heroH*0.8)) * 0.25

     Applied via:
       wheel.style.transform = 'rotate(' + rotation + 'deg) translateY(...)';
       wheel.style.opacity = opacity * 0.25;

     The wheel rotates as you scroll, drifts downward slightly (parallax),
     and fades out as the hero scrolls offscreen.

7.2  Reveal-on-Scroll (IntersectionObserver)

     Targets:    All elements with class .reveal (service cards, price cards,
                 about columns, contacts, map placeholder).

     Initial:    opacity: 0; transform: translateY(30px)  (CSS in main.css)
     Revealed:   opacity: 1; transform: translateY(0)     (class .revealed)
     Transition: var(--transition-slow) = 0.6s ease

     Observer:   threshold: 0.12 (triggers when 12% of element is visible).
                 Once revealed, unobserve() is called — one-shot animation.

7.3  Count-Up Animation (Stats)

     Targets:    .stat__number[data-target] elements (3 total in About section).
     Values:     10+ (years), 5000+ (customers), 50+ (car brands)

     Observer:   threshold: 0.5 (triggers when 50% visible — ensures user sees
                 the animation from the start).

     Animation:  requestAnimationFrame loop, 1500ms duration.
                 Easing: cubic ease-out — 1 - (1 - progress)^3
                 Numbers format with toLocaleString('en-US') + '+' suffix.

7.4  Stagger Delays

     Applies incremental transitionDelay to .reveal elements inside:
       .services__grid — 6 cards, delays: 0ms, 100ms, 200ms, 300ms, 400ms, 500ms
       .prices__grid — 3 cards, delays: 0ms, 100ms, 200ms

     Creates a cascading reveal effect as cards appear one-by-one.

================================================================================
 13. GUEST WALL — TECHNICAL FLOW
================================================================================

13.1  Page Load

  1. wall.js loads, IIFE executes immediately.
  2. Grabs DOM elements by ID (wallMessage, charCount, wallSubmit,
     wallError, wallMessages, wallLoading).
  3. Registers input listener on textarea for character counter.
  4. Calls loadMessages().
  5. loadMessages() fetches GET from API_URL + '?limit=20' with
     { redirect: 'follow' }.
  6. On success: JSON parsed, renderMessages() called.
  7. On failure: showDemoMessages() called as fallback.

13.2  Submitting a Message

  1. User types message, clicks "Leave Your Mark" (or Ctrl/Cmd+Enter).
  2. handleSubmit() fires:
     a. Trims input text.
     b. Hides any previous error.
     c. Calls FixinModeration.check(text) — client-side filter.
     d. If moderation fails: shows error, returns early.
     e. Disables submit button (prevents double-submit).
  3. Creates URLSearchParams body with { message: text }.
  4. Sends POST to API_URL:
     - method: 'POST'
     - mode: 'no-cors' (opaque response — can't read body)
     - Content-Type: application/x-www-form-urlencoded
  5. On .then() (request sent, network OK):
     a. addOptimisticMessage(text) — inserts card at top of wall
        immediately, before server confirms.
     b. Clears textarea, resets character counter.
     c. setTimeout(loadMessages, 2000) — refreshes from server after
        2 seconds to get the canonical list.
  6. On .catch(): shows "Failed to send. Please try again."
  7. .finally(): re-enables submit button.

13.3  Optimistic UI

  Messages appear instantly in the DOM via addOptimisticMessage().
  The card is prepended before the first existing .wall__message.
  If the wall was empty, the "No messages yet" placeholder is removed.
  2 seconds later, loadMessages() re-fetches the full list from the
  server, replacing all cards with the canonical data.

13.4  CORS Strategy

  Google Apps Script web apps redirect on both GET and POST.

  GET:  fetch(url, { redirect: 'follow' })
        Follows the redirect chain. Response is readable JSON.

  POST: fetch(url, { mode: 'no-cors' })
        Returns an opaque response (status 0, body unreadable).
        Success is inferred from the absence of a network error.
        The 2-second delayed GET confirms the message was stored.


================================================================================
 14. GOOGLE APPS SCRIPT BACKEND (Code.gs)
================================================================================

File:           apps-script/Code.gs (169 lines)
                Stored in the repo for version control / reference.
                Must be manually pasted into the Apps Script editor.

Deployment:     Extensions > Apps Script > Deploy > Web app
                Execute as: Me (the Google account owner)
                Who has access: Anyone
                Produces a URL like:
                https://script.google.com/macros/s/.../exec

Sheet:          SHEET_NAME = 'Messages'
                Columns: A (timestamp), B (message), C (status)
                If the sheet doesn't exist, getSheet() creates it
                with headers automatically.

14.1  doPost(e) — Receiving Messages

  Input:        e.parameter.message (URL-encoded form data)

  Validation:
    1. Empty check — rejects if blank
    2. Length check — rejects if > 200 characters
    3. Duplicate check — isDuplicate() (see 14.3)
    4. Moderation — moderate() (see 14.4)

  If moderation passes: status = 'approved'
  If moderation fails:  status = 'rejected'

  Both approved and rejected messages are stored in the sheet
  (rejected ones kept for audit purposes).

  Row written: [ISO timestamp, message text, status]

  Response: JSON { success: true/false, status: 'approved'/'rejected' }
  (Note: client uses mode: 'no-cors', so this response is unreadable
  from the browser. It's useful for curl / direct testing only.)

14.2  doGet(e) — Reading Messages

  Input:        e.parameter.limit (optional, default 20, max 100)

  Process:
    1. Gets the sheet, reads all rows.
    2. Iterates backwards (newest first).
    3. Collects only rows where status === 'approved'.
    4. Stops after reaching the limit.
    5. Converts Date objects to ISO strings.

  Response: JSON array of { text, timestamp } objects.

  On error: returns empty array [] (fails silently).

14.3  Rate Limiting — isDuplicate(sheet, text)

  Checks the last 10 rows in the sheet.
  If any row has the same message text AND was written within the
  last 30 seconds (30000ms), it's flagged as a duplicate.

  This prevents accidental double-posts and spam.

14.4  Server-Side Moderation — moderate(text)

  Identical to the client-side filter (same 25 regex patterns).
  Uses the same normalize() function for leet-speak substitution.

  Returns true (allowed) or false (blocked).

  Rejected messages are still written to the sheet with status 'rejected'
  for auditing. They are never returned by doGet().

 15. CONTENT MODERATION SYSTEM
================================================================================

File:           js/moderation.js (75 lines) — client-side
                apps-script/Code.gs — server-side duplicate

Architecture:   Dual-layer filtering. The same patterns run in both places.
                Client-side: provides instant feedback to the user.
                Server-side: protects against bypassed client filters
                             (DevTools, curl, direct API calls).

15.1  Philosophy

  Profanity IS allowed — keeps the guest wall feeling authentic and lively.
  Only hard-offensive content is blocked:
    - Racist and ethnic slurs
    - Misogynistic violence
    - Homophobic slurs
    - Calls to violence / genocide
    - Extremist symbols and phrases

15.2  Blocked Patterns (27 on client, 25 on server)

  The patterns use word boundaries (\b) and case-insensitive flags (/i).

  Categories:
    Racial slurs:           n-word variants, k*ke, sp*c, ch*nk,
                            w*tback, g**k, c**n, darkie, raghead, towelhead
    Misogynistic:           "kill (all) women", "women deserve (to) die"
    Homophobic:             f-slur, t-slur, dyke
    Violence/extremism:     "kill all/them/every", "genocide is good/based/needed",
                            "gas the/all", "exterminate", "ethnic cleansing",
                            "holocaust was fake/hoax/didn't", "race war",
                            "white power", "heil hitler", "1488", "sieg heil"

15.3  Leet-Speak Normalization

  The normalize() function converts common substitutions before checking:
    0 → o          (e.g. "g00k" → "gook")
    @ → a          (e.g. "f@ggot" → "faggot")
    1 → i          (e.g. "n1gger" → "nigger")
    3 → e          (e.g. "n3gro" → "negro")
    $ → s          (e.g. "$ieg" → "sieg")

  Also lowercases and trims the text.

15.4  Client-Side Check (FixinModeration.check)

  Exposed as a global object via IIFE + return pattern.
  Called as: FixinModeration.check(text) → { pass: boolean, reason: string }

  Also validates:
    - Empty/whitespace-only messages → "Message cannot be empty"
    - Over 200 characters → "Maximum 200 characters"
    - Pattern match → "Message contains inappropriate content"

15.5  XSS Prevention

  All user-generated message text is rendered via textContent, never
  innerHTML. This prevents script injection regardless of what the
  user types. The createMessageCard() function in wall.js creates
  DOM elements programmatically and sets text content safely.

 16. SMOOTH SCROLLING
================================================================================

File:           js/smooth-scroll.js (37 lines)
                Wrapped in IIFE.

Behavior:       All anchor links (a[href^="#"]) get a click handler.

  1. Prevents default jump behavior.
  2. If the mobile menu is open, closes it first.
  3. Calculates the scroll offset:
     offset = --banner-height + --nav-height (read from computed styles)
     This accounts for the fixed banner and sticky nav.
  4. Scrolls to the target section using window.scrollTo() with
     behavior: 'smooth'.

  Links to "#" (logo link) do nothing — guarded by early return.

 20. JAVASCRIPT ARCHITECTURE
================================================================================

20.1  No Globals (Almost)

  Every JS file wraps its code in an IIFE (Immediately Invoked Function
  Expression): (function() { ... })();

  Exception: moderation.js exposes `FixinModeration` as a global object
  because wall.js depends on it. This is the ONLY intentional global.

20.2  No Build Tools

  All scripts are vanilla ES5-compatible JavaScript.
  No transpilation, no bundling, no minification.
  Can be served from any static file server.

20.3  Performance Patterns

  - passive: true on scroll listener — prevents layout thrashing
  - requestAnimationFrame throttling — one animation tick per frame
  - IntersectionObserver — no scroll-position polling for reveals
  - unobserve() after reveal — no continued observation of visible elements
  - will-change: transform — GPU layer hint for animated elements
  - Early return guard (scrollY < heroH * 1.2) — no work when hero is
    offscreen
  - DocumentFragment for bulk DOM insertion (renderMessages)

20.4  Script Loading Order

  All 5 scripts are at the end of <body> (before </body>).
  They execute synchronously in order:
    1. scroll-animation.js — safe to run first, queries DOM elements
    2. smooth-scroll.js — attaches click listeners to anchors
    3. mobile-menu.js — attaches click listener to hamburger
    4. moderation.js — defines FixinModeration global
    5. wall.js — uses FixinModeration, starts loadMessages()

 25. HOW TO SET UP FROM SCRATCH
================================================================================

25.1  Local Development

  1. Clone or download the project folder.
  2. Open a terminal in the project root (freelance/).
  3. Start a local server:
       python3 -m http.server 8000
  4. Open http://localhost:8000 in a browser.
  5. The site works fully offline — guest wall shows demo messages.

25.2  Google Apps Script Setup (for live Guest Wall)

  1. Create a new Google Sheet (any name).
  2. Go to Extensions > Apps Script.
  3. Delete the default Code.gs content.
  4. Paste the contents of apps-script/Code.gs.
  5. Click Deploy > New deployment.
  6. Set type: Web app.
  7. Execute as: Me.
  8. Who has access: Anyone.
  9. Click Deploy. Copy the web app URL.
  10. Open js/wall.js and replace the API_URL value with your URL.
  11. The "Messages" sheet tab is created automatically on first request.

25.3  Deploying to GitHub Pages

  1. Push the project to a GitHub repository.
  2. Go to Settings > Pages.
  3. Source: Deploy from a branch.
  4. Branch: main, folder: / (root).
  5. The site will be live at https://username.github.io/repo-name/
